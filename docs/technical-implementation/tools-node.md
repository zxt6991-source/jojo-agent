# Tools Node 技术实现方案

路径：`packages/tools-node`  
包名：`@desktop-agent/tools-node`

## 1. 定位与安全边界

Tools Node 提供 Node.js 环境中的本地能力及默认权限策略。当前包含 `read_file`、`list_files`、`terminal` 三个工具和 `DefaultPermissionGate`。

权限 Gate 决定“允许、拒绝或询问”，工具执行器仍会再次校验路径。这种双层校验防止调用方绕过 Gate 直接执行时失去基本边界。

## 2. 路径安全模型

所有路径以会话工作目录为基准，先 `path.resolve`，再用 `realpath` 解析真实目标，最后通过 `path.relative` 判断是否位于真实根目录中。这样同时处理：

- `../` 路径穿越；
- 绝对路径；
- 指向目录外的符号链接；
- 不同平台的路径分隔符。

目标不存在时 `realpath` 会失败，由 Agent Core 转为工具错误或由 Gate 拒绝。当前工具面向读取已有文件，不支持尚未创建的目标路径。

## 3. 工具实现

### 3.1 `read_file`

读取 UTF-8 普通文件，默认最多 512,000 字节。工作目录内自动允许，目录外需逐次批准；即使被批准，仍要求目标是普通文件。超限时截断并返回 `truncated`。

### 3.2 `list_files`

递归列出工作目录内目录，深度为 0～5，默认最多 500 个条目。忽略 `.git`、`node_modules`、构建输出和缓存目录，按名称排序，并跳过解析后越界的符号链接。目录外列表请求直接拒绝，不提供审批升级。

### 3.3 `terminal`

使用 `spawn(command, args)` 执行单个程序，`shell: false`，工作目录必须位于会话目录内。每次调用都需审批。stdout/stderr 实时上报，汇总输出默认最多 1,000,000 字节；超时范围 1～300 秒，默认 120 秒。

非 Windows 平台使用独立进程组，取消或超时时向整个进程组发送 `SIGTERM`；Windows 终止子进程本身。结束结果包含退出码/信号，并区分启动失败、非零退出和取消。

## 4. 默认权限矩阵

| 工具 | 工作目录内 | 工作目录外 |
|---|---|---|
| `read_file` | 自动允许 | 询问一次 |
| `list_files` | 自动允许 | 拒绝 |
| `terminal` | 每次询问；`cwd` 必须在目录内 | 拒绝越界 `cwd` |

Terminal 审批只代表用户看过命令，不是操作系统沙箱。获批程序仍继承应用用户权限，且参数可能访问工作目录外资源。

## 5. 输出与资源限制

文件、目录和终端均设置上限，避免大输入占满 Agent 上下文或应用内存。Terminal 一边流式上报、一边累积有限结果；达到上限后继续等待进程结束但不再收集更多内容。

当前超时触发与普通 SIGTERM 结束共享退出结果，尚未单独返回 `timeout` code；若 UI 需要准确区分，应增加显式超时状态并在进程未退出时升级到强制终止。

## 6. 测试方案

现有测试覆盖大文件截断、符号链接越界和目录外审批。后续优先补充：

1. `..`、绝对路径、目录目标、损坏符号链接；
2. 列表深度、忽略目录、条目上限与稳定排序；
3. Terminal stdout/stderr、非零退出、启动失败、超时与取消；
4. 子进程树回收和 Windows 行为；
5. 所有 Zod 输入边界与未知工具拒绝。

## 7. 演进方案

- 将路径授权抽成可复用的 Workspace Policy，供未来写文件和补丁工具共享。
- 对 Terminal 增加超时后 `SIGKILL`/平台等价动作的有界升级策略。
- 引入只读/写入/进程/网络等能力标签，让审批 UI 能展示统一风险级别。
- 新增写工具时采用临时文件 + 原子替换，并在执行前生成可审阅变更，不能复用读取工具的宽松授权。
