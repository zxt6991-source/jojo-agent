# 对话内生成 HTML 文档

## 轨迹中的问题

《按格雷厄姆稳健标准筛选10只A股》轨迹第 3 轮：用户 #26 要求“回答输出到 html 文档”，工具 #29 用 `write_file` 写入工作目录，助手 #30 只返回反引号包裹的文件名，让用户自行找到文件打开。

文件确实生成了，但交付缺少对话内的文档入口。上传附件的解析流程负责读取用户输入，不负责展示助手生成的文档；只调整 HTML 提取器不能解决这个问题。

## 当前行为

- `create_document({ name, content })` 接收完整 HTML，通过工具调用记录随会话保存，不单独写入项目、桌面或下载目录。
- Desktop 的指令引导 HTML 报告使用这个工具；用户明确指定本地或项目文件时仍使用文件工具。
- 对话视图从成功的工具记录生成卡片，展示文件名、HTML 预览以及“下载保存”。工具运行中、失败或中断时不展示可交付卡片。
- 用户点击“下载保存”后由主进程弹出系统保存对话框；确认路径后才写文件。取消不写文件，写入失败在卡片中显示错误。
- 成功的旧 `write_file` HTML 调用也可以展示卡片，内容来自当时调用的完整输入快照，不读取任意本地路径。因此旧文件之后被其他工具编辑时，卡片仍代表该次生成版本。

## 边界

目前只支持 `.html` / `.htm`，内容上限 2,000,000 字符。新文档没有独立的工作区文件，但内容仍存储在本地会话历史中。现有会话压缩与历史保留规则继续适用。

预览使用 DOMPurify、无权限的 sandbox iframe 和限制性 CSP，禁止脚本、表单、嵌入页面及外部资源；保留内联样式。下载保存的是原始 HTML。生成时应使用完整、离线可读的 HTML 和内联 CSS。

Excel、PDF、图片及其他二进制产物的统一交付不在此次实现范围内。

## 验证

- 工具测试：无需有效工作目录即可生成，拒绝路径和不合法文件名。
- 会话渲染测试：新工具和旧 HTML 写入记录均能生成卡片，失败调用与非 HTML 文件不会生成卡片。
- Electron 端到端测试：真实工具调用、预览样式、脚本隔离、阻止外部请求、刷新恢复、取消保存及确认保存。
