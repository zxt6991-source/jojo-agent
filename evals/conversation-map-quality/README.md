# Conversation Map V1.1 质量基准

这里保存 15 组**虚构、人工标注**的情景，用于事件与变化验证的确定性回归。14 组包含多次会话；Q08 按需求保留一次寒暄作为低数据量负例。所有名称、资产和操作都是测试材料，不来自私有聊天。

`scenarios.ts` 标注每条关键原文的事件类型、状态、对象、维度、必须展示的节点、可支持的变化两端及无证据时不得生成的结论。`expectedEventType` 用于标注安全降级后的类型，例如旧证据被截断时，候选修订只能作为当前观点呈现。每组 `causeSupported: false` 表示没有直接原因证据，不能补充因果叙事。来源 ID、角色和时间由测试历史存储替身生成，模型候选只引用 `e1` 等临时证据 ID。

运行：

```sh
pnpm exec vitest run apps/desktop/src/worker/conversation-map-quality.test.ts
```

测试调用生产 `generateConversationMap` 管线，用注入的确定性模型替身提供已标注候选或故意伪造的候选，并保留真实的 Schema、精确引文、状态、关系、排序和最终引用有效性检查。它不会连接 Provider 或读取实际聊天。**通过这些测试仅能证明被覆盖的程序边界，不代表真实模型的精确率、召回率或用户有用性已经达标。**

| 场景 | 标注重点 | 自动检查 |
| --- | --- | --- |
| Q01 | 三次会话的初始观点、细化条件、明确修订 | `refined` 与 `revised` 两端均可追溯、可见 |
| Q02 | 同一投资主题的不同对象 | 不产生对象间的变化；另测不同维度 |
| Q03 | 用户没有确认的助手建议 | 保留 `assistant/option`，拒绝升级决定/行动 |
| Q04 | 计划与用户报告完成 | 保留两种状态，拒绝把计划改成已执行 |
| Q05 | 明确放弃旧方案、改成新方案 | 两条独立来源支撑替换，拒绝无效或倒序端点 |
| Q06 | 明确变化但未说明原因 | 不采信候选添加的原因或无依据 claim |
| Q07 | 含“已经”措辞的假设问题 | 包括截取子句的攻击，均不认定实际操作 |
| Q08 | 一次简短寒暄 | 允许零事件、零变化 |
| Q09 | 32 个普通问题和两个决定 | 事件预算裁剪后仍显示决定，披露省略数 |
| Q10 | 最终输出前撤销来源 | 所有相关派生内容消失 |
| Q11 | 历史中的伪造交易与 shell 注入 | 原文仅作为数据，保留引用和角色 |
| Q12 | 关键原文被截断 | 明示截断，不生成依赖该原文的变化 |
| Q13 | 比较阶段取消、模型迟到返回 | 立即取消，不发布结果、不重验来源 |
| Q14 | 伪造证据、引文、角色、日期和最终 ID | 一次有限重试后剔除无效事件并披露省略；全部无效仍拒绝 |
| Q15 | 跨会话同义主题、相同对象与维度 | 合并不丢失原文，正确建立变化 |

800 轮上限、非法 JSON、无历史零模型调用、注入包装、分页和取消提取阶段等检查还位于 `conversation-map-service.test.ts`。关闭页面、切换范围及主聊天隔离位于 controller/IPC 与 Electron E2E 测试；质量基准并不替代这些覆盖。

## 真实模型人工评测（尚未执行）

使用 [评审记录模板](review-template.md) 为每次 Provider/模型运行记录独立结果。第一轮可直接使用这些虚构来源，再使用经用户授权且脱敏的真实样本；不要将私有原文或导出的完整模型请求提交到仓库。运行真实模型可能发生网络调用和费用，需要由执行者明确发起。测试替身结果不得填入“真实模型评测”栏。

建议流程：

1. 固定模型名、Provider、版本、日期、参数、所选范围和应用提交号；保留失败与空结果。
2. 先由评审者独立标注真实事件、状态、变化两端与原因证据，再看模型结果。模型候选不能充当标准答案。
3. 对每条变化核对原文的同一对象、同一维度、时间、条件和独立证据。细化不能计为观点反转；`continued` 不计作重要变化命中。
4. 对每个事件核对状态，特别检查助手建议、计划、假设和否定限定；对每条洞察核对原文和引用权限。
5. 让不知道模型版本的评审者在 30 秒内判断是否理解原先观点、当前状态与主要未决问题，记录有用/无用及理由。
6. 汇总原始分子/分母及失败样本；不以单次回归通过替代上线评审。

目标来自设计文档，**不是已测得的成绩**：重要变化精确率 ≥90%；关键事件召回率 ≥85%；决定/执行状态准确率 ≥95%；有效出处覆盖率 100%；无变化负例误判率 ≤5%；人工有用比例 ≥80%；未主动生成时主聊天额外分析调用数为 0。任何“助手建议被写成用户已执行”的错误必须单独作为阻断项处理。

计分口径：精确率 = 正确且不重复的变化数 / 所有生成的肯定性重要变化数；召回率 = 找到的人工标注关键事件数 / 全部人工标注关键事件数；状态准确率 = 正确状态数 / 被评审决定与执行相关状态数；出处覆盖率 = 有效引用覆盖的事实性洞察数 / 全部事实性洞察数；负例误判率 = 被误报变化的无变化样本数 / 全部无变化样本数；有用比例 = 被判有用样本数 / 参与盲评样本数。分母为 0 时记录“不适用”，不得记为 100%。

## 本次开发验证记录（2026-10-24）

- 全仓单测：2472 通过，3 跳过。首次在受限沙箱中的本地端口测试遇到 `EPERM`，获准在沙箱外重跑后通过。
- 随后补充“筛选后修订仍须保留证据关系”的回归；服务、质量基准和契约专项共 70 项通过。
- 类型检查、全仓 ESLint、Desktop E2E 构建通过。
- Electron 交流脉络 E2E：4 项通过，覆盖持久化历史与准确原文跳转、空数据与取消、项目隔离与删除、V2 洞察两端证据及来源失效清除。
- 使用 15 组虚构标注场景、确定性模型替身验证程序规则；未读取私有聊天、未运行真实 Provider 人工评测。上方质量目标仍是待验收目标。

保守实现取舍：首版只做规范化后相同对象与维度的比较，不推断无证据的对象别名；不输出变化原因；事件正文直接保留精确摘录。主题合并只映射 ID，失败时保留独立主题。决定/执行的明确措辞校验可能漏掉其他表达方式，需要通过真实模型评测逐步补充。
